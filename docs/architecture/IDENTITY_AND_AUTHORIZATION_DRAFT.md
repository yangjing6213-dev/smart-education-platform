# 身份与授权草案

## 1. 统一用户模型

```text
User
├─ 微信身份（未来）
├─ 手机号身份（未来）
├─ 网页登录身份（未来）
└─ 一个或多个机构 Membership
```

`User` 表示同一自然人的平台主体；登录身份只负责证明主体，不能直接授予业务权限。`Membership` 表示 User 与一个 Tenant 的成员关系，并承载状态、角色和数据范围。当前原型均为模拟身份，不接真实微信、短信、手机号或密码。

学生首期不独立注册，不拥有 User、Membership 或授权角色。受监督学生交互由家长或教师从已有学生档案开启。

## 2. 核心概念

| 概念 | 责任 | 关键守卫 |
|---|---|---|
| User | 聚合多个登录身份的稳定主体 | 身份合并须独立验证，不以手机号文本直接合并 |
| Identity | 微信/手机号/网页登录凭据映射 | 凭据环境隔离、可撤销；本批次不实现 |
| Membership | User 与 Tenant 的关系 | 必须有效、不能跨租户复用 |
| Role | 能力集合的命名 | 只在当前 Membership 内生效 |
| Permission | 对资源与动作的最小许可 | 默认拒绝，不能仅靠页面隐藏 |
| DataScope | 校区、班级、学生关系、本人、对象等范围 | 与 Permission 同时满足才放行 |

### 2.1 家长绑定前的受限 OnboardingScope

家长首次绑定时尚无机构 Membership，不能套用成员权限。未来流程先验证平台 `User` 身份，再由服务端校验一次性机构邀请码；服务端解析候选 `tenant_id`、`campus_id` 和学生匹配范围，签发短时、不透明、一次性 `OnboardingScope` token。客户端提供的邀请码、学生姓名或班级只作为匹配输入，不是租户、校区、学生或权限的权威来源。

`OnboardingScope` 只允许提交绑定申请和查询本人申请状态，不允许读取学生档案、机构成员数据或其他申请。错误统一为通用无效/不可继续，避免枚举机构、校区、班级或学生。审核通过时，在同一事务内创建或激活家长 Membership、建立 `GuardianRelationship`、关闭申请并消费该 scope；审核拒绝、撤回或 scope/邀请码过期时不创建 Membership 或关系。

## 3. 七个基线角色

| 角色 | 基本能力 | 数据范围 | 明确禁止 |
|---|---|---|---|
| 访客 | 读取已发布公开内容，提交最小模拟意向 | 指定机构公开投影 | 内部内容、草稿、学生数据、后台 |
| 家长 | 管理本人绑定/请假/接送与 AI 监督；查看已批准关系孩子的家长限定学习摘要 | 当前租户内已通过关系的学生，必要时限校区 | 未关联学生、教师内部/待复核摘要、模型内部日志、其他孩子数据、后台 |
| 教师 | 任务、班级必要记录、教师日报、AI 监督与摘要 | 当前租户、授权校区、班级/任务/学生 | 未授权班级、自动纪律/绩效结论、外发摘要 |
| 工作人员 | 内部指南、资源、伙伴云入口与岗位操作 | 当前租户、授权校区、岗位资源 | 默认学生内容、教师日报、发布和角色管理 |
| 机构管理员 | 机构内容、成员、审核、文件与日志 | 单一当前租户及获授权校区；敏感对象另校验 | 其他租户、AI 摘要正文、篡改审计 |
| 校区负责人 | 授权校区的成员、流程、日报和汇总 | 当前租户 + 明确 `campus_id` | 其他校区/租户、AI 摘要正文、自动绩效结论 |
| 平台管理员 | 租户目录、平台配置和运行元数据 | 默认只有平台元数据 | 默认学生/家庭/健康/接送/AI 正文及无审计跨租户访问 |

角色名称与范围必须与 `docs/product/ROLE_MATRIX.md` 一致。学生不是第八个角色。

## 4. 权限判定

```text
验证身份
→ 选择有效 Membership
→ 选择一个当前角色
→ 校验租户状态
→ 注入 tenant_id
→ 校验并注入 campus_id / 班级 / GuardianRelationship / 本人 / 对象范围
→ 校验资源、动作和对象状态
→ 执行或默认拒绝
→ 敏感动作追加审计
```

控制器/API 入口完成认证和基础范围形成，应用服务执行资源/动作/对象状态策略，仓储层强制附加租户/校区范围形成纵深防御。客户端传入的 `tenant_id` 不是授权输入。

### 4.1 RequestScope 版本与指纹

服务端统一 `RequestScope` 至少包含：`user_id`、`membership_id`、当前 `role_id`、`tenant_id`、规范化 `campus_id` 集合、班级集合、学生/GuardianRelationship 范围、权限集合，以及 Membership、角色/权限策略、校区/班级授权、家长关系等相关版本。服务端对规范序列计算不透明 `scope_fingerprint`，同时携带 `scope_version`；两者都不能由客户端提供或覆盖。

任一身份、角色、权限、校区、班级、学生关系、Membership 状态或相关版本改变，都必须形成新指纹并拒绝旧范围。`OnboardingScope` 使用独立受限指纹，审核通过后不能升级复用；必须以新 Membership 重新形成完整 RequestScope。

## 5. 多角色与多机构切换

- 用户必须显式选择一个 Membership 与其中一个角色；页面显示当前机构、校区和角色。
- 切换时重新签发/形成服务端上下文并重新计算权限，不把多个角色合并成超集。
- 切换失败时保留原安全上下文或退出，不沿用目标角色的局部权限。
- 浏览器标签页、缓存和异步任务均绑定上下文版本；Membership 停用后失效。

## 6. 家长与学生关系

家长权限来自已通过且未解除的 `GuardianRelationship`，不来自知道学生姓名、班级或邀请码。绑定必须经历微信登录概念、手机号、邀请码 + 学生姓名 + 班级、服务端受限 OnboardingScope、机构审核、事务性创建/激活家长 Membership 与建立关系的锁定顺序。拒绝、解除或关系失效后立即停止读取学生内容。家长除监督开关、会话状态和安全提示外，只能查看 A2 规定的家长限定投影：本人已批准绑定孩子的使用时长、完成情况、知识点摘要及已通过人工复核的需关注项；不得读取教师内部/待复核摘要正文、模型内部日志或其他学生数据。

## 7. 教师班级范围

教师 Membership 关联一个或多个获授权班级/任务范围。读取或写入学生记录、接送、异常、日报汇总和 AI 摘要时，同时校验租户、校区、班级与对象。班级调动或权限撤销后旧缓存和会话失效。工作人员角色不能借同一 User 自动继承教师范围。

## 8. 管理权限

- 机构管理员只能管理当前租户内允许的内容、成员、审核和日志；敏感学生对象仍需单独业务权限。
- 校区负责人所有管理操作均受明确 `campus_id` 限制，不能因机构内角色扩大为全机构。
- 角色分配者不能授予超过自身租户、校区或能力范围的权限。
- 平台管理入口与机构管理网页分离；平台管理员的受控支持例外要求单独批准、最小字段、限时和审计。
- 教师教学摘要正文仅授权教师可读；家长只读本人有效关系孩子的 A2 限定投影，机构管理员、校区负责人和平台管理员最多读取不含正文的审计元数据。

## 9. 拒绝、审计与撤销

无 Membership、状态失效、角色不符或范围冲突统一默认拒绝，不泄露对象是否存在。跨租户/校区尝试、角色分配、绑定审核、文件授权、发布、AI 会话开启和受控支持访问写入最小审计。登出、Membership 停用、关系解除、机构开关关闭或高风险事件可撤销会话与授权。

本批次不实现认证协议、密码策略、令牌格式、真实账号恢复或生产管理员流程。

## 10. 统一账号身份、成员冻结与会话撤销（R2 离线契约）

本节是对未来正式接入的设计约束，不代表相应能力已经实现。稳定的平台主体 `User`、用于证明登录者身份的 `Identity`、机构范围内的 `Membership` 和一次已认证的 `Session` 是不同对象；登录凭据不能直接携带或授予机构角色。

### 10.1 身份关联与账号保护

- 每条 `Identity` 必须由服务端映射到一个稳定 `user_id`；身份提供方的标识需连同提供方、发行方和运行环境一起判重，测试身份不得与正式身份共用命名空间。外部凭据本身不作为业务对象 ID。
- 只有验证成功的身份才可以用于登录或关联。身份关联与换绑必须证明当前账号控制权，并单独验证待关联身份的控制权；仅有相同手机号文本、姓名、学生信息或机构邀请信息不能合并两个 `User`。同一外部身份已关联到另一 `User` 时必须拒绝并进入账号恢复/人工核验流程，不得自动转移或覆盖。
- 解绑身份前必须确认账号仍有另一种已验证且可用的登录方式；否则阻止解绑并引导到已批准的恢复流程。无法验证当前身份、换绑冲突或恢复材料不足时默认拒绝，不以客服口头确认代替可审计的核验步骤。
- 邀请与绑定申请只能建立待处理关联，不能证明登录身份，也不能使成员提前生效。邀请失效、撤回、重复使用或申请被拒后不能创建可访问的 `Membership`；家长待审核阶段继续受第 2.1 节 `OnboardingScope` 限制。

### 10.2 Membership 冻结和授权版本

- `INVITED`、`SUSPENDED` 和 `REVOKED` 均不得形成有效 `RequestScope`。只有 `ACTIVE` Membership 可在重新检查租户、校区、角色、对象关系及业务状态后获得最小权限；客户端给出的状态或范围一律不作为可信依据。
- 每次暂停、撤销、恢复、角色变化、校区/班级范围变化或相关关系变化都必须推进相应授权版本。服务端需要能识别已过期的 Membership、角色/范围版本和 `scope_fingerprint`，并在受保护请求执行前拒绝旧上下文；重新激活不得恢复旧会话、旧令牌或旧缓存。
- `SUSPENDED` 表示可在重新核验并显式恢复后重新申请访问；`REVOKED` 表示现有成员关系终止，不能通过普通状态更新重新激活。若确需重新加入，必须走新的邀请/审批，并保留前后关系可区分的审计轨迹。
- 冻结一个 Membership 至少撤销所有绑定该 Membership 的会话及其作用域；撤销一个 `Identity` 应撤销由该身份建立的会话；账号整体停用或安全事件则撤销该 `User` 的全部会话。只影响一个 GuardianRelationship 的变化必须清除涉及该关系的家长作用域，不能保留旧学生内容缓存。
- 登出只结束当前会话；密码/身份安全事件、账号停用、角色或范围变更应按其对象范围撤销相应会话。多机构或多角色用户一次只选择一个 Membership/角色，切换后重新解析范围，不拼接权限集合。

### 10.3 Session 形成、续期与撤销

- 登录成功后服务端从已验证身份解析 `user_id`，由服务端解析可用 Membership；客户端仅提交所选的 Membership 标识作为选择请求，服务端再次验证其归属、状态、租户和权限。客户端不得提交可覆盖的 `tenant_id`、角色、校区、班级或学生关系。
- 会话应引用身份和当前 Membership，并由服务端在每个受保护操作前验证会话有效期、撤销状态和授权版本，再形成第 4.1 节的 `RequestScope`。会话句柄不应承载可由客户端修改的权限快照；角色、成员、校区或关系变化后必须拒绝旧作用域。
- 浏览器正式会话沿用基线要求的 `Secure`、`HttpOnly`、`SameSite` Cookie、短时有效及权限变化时轮换；具体有效期、续期策略与 Mini 的安全存放方式保持未决，需按最终认证提供方、平台安全能力和威胁模型确定。不得把本机 Bearer 演示句柄照搬为生产令牌。
- 权限收回的产品要求是：状态变更提交后，之后发起的受保护请求不得继续使用被撤销的权限。未来实现必须验证网页、管理网页和 Mini 的旧会话、并发请求、缓存及后台任务均按相同规则失效；事件通知、短轮询、版本检查或其他传播方式及其最大生效时限需在实际部署方案中明确，不在本草案虚构数值。
- 会话失效后不得静默降级为更宽权限；应重新认证/选择有效身份和 Membership，失败时默认拒绝并提供不泄露账号或对象存在性的通用提示。

### 10.4 审计和失败处理

身份关联、换绑、解绑、恢复、邀请接受/撤回、成员暂停/恢复/撤销、角色或范围变化、会话撤销均应记录执行者、目标 `user_id`/`identity_id`/`membership_id`、变更前后状态、结果和时间；审计中不得记录口令、令牌、验证码或完整认证材料。读者仍按第 8、9 节权限隔离。记录期限和删除/备份规则由 R6 与正式运营审阅决定。

权限缺失、身份冲突、已失效邀请、旧版本、跨租户/校区选择及身份枚举请求均默认拒绝。面向客户端的错误不得透露账号是否存在或身份当前绑定到谁；内部审计可记录稳定的失败类别供授权人员排障。

### 10.5 后续真实接入验收清单

正式实现必须至少验证：

1. 同一 User 的多个已验证身份均解析到同一主体；未验证身份不能登录或关联；不同环境身份不能串用。
2. 同一外部身份并发关联到两个账号时只有一个操作成功，另一个返回通用冲突；不同手机号文本相同或姓名/学生字段相同不会自动合并账号。
3. 邀请未接受、已过期、已撤回、重复消费及绑定待审核均不能读取学生或成员资料；通过审核后使用新 Membership 范围，不把 `OnboardingScope` 升级复用。
4. 已签发会话后暂停或撤销 Membership，网页、管理网页和 Mini 的后续受保护请求均被拒绝；恢复 Membership 后旧会话仍拒绝，只有重新认证才可建立新会话。
5. 身份解绑/撤销、角色或校区范围改变、学生关系解除后，受影响旧会话、缓存、异步任务和学生数据读取都不能继续使用旧范围；无关 Membership 按其自身权限继续工作。
6. 最后一个已验证登录方式不能在无可用恢复办法时被移除；换绑冲突、账号恢复失败和身份枚举均走默认拒绝及通用提示。
7. 每个敏感变更都能追溯到授权执行者、目标对象、结果和版本；审计不包含认证秘密。拒绝测试同时覆盖本人/跨租户/跨校区和不匹配对象。

上述清单是未来接入验收要求，不是当前通过结果。本地 `LocalSessions` 以进程内 `Map` 保存固定合成会话、成员状态/版本和演示审计；状态暂停时可在同一进程使旧句柄失效，不能证明多进程、跨设备、重启后、缓存/任务或正式提供方的一致撤销。当前 `authPlugin` 通过注入的可信认证结果解析上下文，不连接任何真实提供方。

**未决决定：** 选用哪些微信/手机号/网页提供方；手机号是否可作为唯一身份键；允许哪些身份组合及账号恢复证明；正式邀请渠道、有效期与重发规则；真实会话时长/续期/并发限制；Mini 令牌存储及平台限制；撤销跨端最大生效时间及实现方式；客服人工核验职责；身份、成员和审计记录的保留期限。决定前不得配置真实登录、迁移账号或声称已具备跨设备撤销能力。
