# 环境与部署草案

## 1. 边界

本文只定义未来环境隔离与候选部署形态。Phase 1A 批次A不创建应用、容器、云资源、域名、流水线或环境变量，不读取/生成生产密钥，也不部署测试或生产环境。

## 2. 概念环境

| 环境 | 用途 | 数据 | 外部能力 | 访问边界 |
|---|---|---|---|---|
| `local` | 单机开发与离线原型 | 仅明显虚构模拟数据 | 默认关闭；不使用生产连接 | 开发者本机；当前仅静态原型 |
| `dev` | 未来共享开发集成 | 合成/种子数据 | 独立沙箱配置，默认最小能力 | 开发团队、受审计管理入口 |
| `test` | 自动测试与安全验证 | 每次可重建的合成数据 | 模拟器/桩优先 | CI/测试主体；无人工生产账号 |
| `staging` | 未来候选发布验证 | 经批准的非生产数据集，禁止复制真实未成年人数据 | 独立非生产应用/账号 | 受限验收人员；与prod无共享密钥 |
| `prod` | 未来生产服务 | 仅在正式治理与同意到位后 | 独立生产账号、密钥与策略 | 最小运维权限、强审计 |

上述环境名称不表示当前已存在。

## 3. 强制隔离维度

- 独立数据库与数据库账号；禁止 local/dev/test/staging 连接生产数据库。
- 独立 COS 桶或达到等价强度的账号/命名空间；生产对象不能被非生产签名。
- Redis 键空间与账号按环境隔离；是否启用由真实需求决定。
- 微信应用、回调地址、AI Provider 项目、RAG 索引、日志、审计和成本账户按环境隔离。
- 密钥独立轮换并由服务端秘密管理注入，不放入 Git、镜像、前端、文档或普通日志。
- 每个环境内仍执行 `tenant_id`、`campus_id`、班级和关系隔离；环境隔离不能替代租户隔离。

## 4. 候选运行拓扑（未来）

```text
Nginx / 受控入口
→ 三端静态/服务端应用入口
→ NestJS模块化单体API（一个或多个无状态实例）
→ PostgreSQL
→ COS
→ Redis（仅经批准按需启用）
→ 外部适配器（微信/AI等，默认关闭）
```

Docker 可用于构建一致运行单元，Nginx 可负责 TLS 终止、路由和基础限制；这只是候选，不构成选型完成或部署授权。数据库迁移需独立审查、备份/回退和单向发布策略，当前不创建。

## 5. 配置与秘密

配置分为可公开的行为配置、受限环境配置和秘密。机构功能开关、家长同意与角色权限属于业务数据，不能通过环境变量绕过；生产密钥、数据库口令、COS/微信/AI 凭据只属于秘密管理。任何缺少必需秘密的环境应安全失败，不填示例真实值、不回退到生产配置。

## 6. 未来交付与发布原则

未来流水线应从同一受审查提交生成不可变产物，经过静态检查、单元/集成/安全测试、迁移预检与人工批准后逐环境提升。不得从开发机直接修改生产。部署与数据库变更分别可回退；状态迁移需要兼容窗口。当前没有流水线、镜像、部署命令或发布结果。

## 7. 可观测性与审计

各环境独立采集健康、错误、延迟和资源指标；日志包含环境、请求关联 ID、服务、租户/校区最小元数据，但不含密钥、令牌、签名 URL、学生或 AI 正文。访问生产日志和支持工具使用最小权限与审计。容量、SLO、RTO/RPO、告警阈值必须基于后续真实约束决定，本批次不虚构数字。

## 8. 已决定与暂缓

已决定：环境必须隔离；生产数据/密钥不得下沉；外部能力按环境独立；服务端统一执行租户权限；部署候选为 Docker + Nginx。

暂缓：云区域/网络、计算规格、数据库托管形态、COS 桶、Redis、域名/TLS、CI平台、镜像仓库、扩缩容、备份/容灾、监控产品、成本预算及正式发布流程。任何后续部署需新任务明确授权。
