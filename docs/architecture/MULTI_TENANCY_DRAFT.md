# 多租户隔离草案

## 1. 安全不变量

1. 所有机构业务对象必须有 `tenant_id`；校区业务必须有 `campus_id`。
2. 服务端从已验证身份、当前 Membership 和授权数据范围注入租户/校区上下文。
3. 不信任客户端提交的租户 ID。请求体、查询参数或普通请求头中的 `tenant_id` 若与可信上下文冲突，直接拒绝并记安全审计；不能用客户端值覆盖。
4. 未明确允许的跨租户、跨校区、跨班级或跨家长关系访问默认拒绝。
5. 平台管理员默认无租户业务内容范围，尤其不得查看学生具体内容。

## 2. 可信上下文形成

```text
已验证 User
→ 选择一个有效 Membership
→ 选择该 Membership 内一个角色
→ 读取角色授权的 tenant_id
→ 解析可用 campus_id / 班级 / 学生关系 / 对象范围
→ 形成不可由业务请求覆盖的 RequestScope
```

角色切换必须重新形成 `RequestScope`。多个 Membership 或角色不能合并为权限超集。公开访客请求没有 Membership，只能解析为指定机构的已发布公共投影范围。

### 2.1 家长绑定的前成员范围

首次绑定用户没有机构 Membership。未来服务端在验证 `User` 后校验一次性机构邀请码，并在服务端解析候选租户、校区与学生匹配范围，签发短时、不透明、一次性 `OnboardingScope`。客户端的邀请码、姓名、班级和任何租户/校区值都只是匹配输入，不是可信范围。

该 scope 仅允许提交绑定申请和查询本人申请状态，所有失败使用通用响应防止机构/学生枚举。机构审核通过时，同一事务创建或激活家长 Membership、建立 `GuardianRelationship`、消费 scope 并关闭申请；拒绝、撤回、过期或匹配冲突时不创建任何关系或成员权限。

### 2.2 RequestScope 指纹与缓存

完整成员请求的 `RequestScope` 由服务端规范化 `user_id`、`membership_id`、当前角色、`tenant_id`、校区/班级集合、学生/GuardianRelationship 范围、权限集合及 Membership/角色/策略/关系等相关版本，并生成 `scope_version` 与不透明 `scope_fingerprint`。任何组成或版本变化都使旧指纹失效。

已经按权限过滤的授权结果缓存，键必须包含环境、`scope_fingerprint`、资源/查询摘要和数据版本；不得只用 user 或 tenant 作为授权缓存键。未按权限过滤的事实缓存只能保存明确租户内的事实，每次返回前都必须以当前 RequestScope 重新授权和字段投影。幂等记录、分页 cursor 与异步任务也不得借旧指纹继续执行；消费者/返回入口重新验证当前范围。

## 3. 隔离面

| 隔离面 | 强制设计 |
|---|---|
| 数据表 | 机构业务行带 `tenant_id`；校区业务行带 `campus_id`；敏感关系继续带班级/学生关系范围 |
| 查询 | 仓储入口必须接受可信 `RequestScope` 并自动添加租户/校区条件；按 ID 查询也不能省略范围 |
| 写入 | 服务端覆盖/注入范围字段；关联对象必须位于同一租户，校区关系必须在授权集合内 |
| 唯一约束 | 业务唯一性至少包含 `tenant_id`，校区局部唯一性再包含 `campus_id`；不定义跨租户全局业务唯一 |
| 缓存键 | 授权后结果包含 `scope_fingerprint`；未过滤事实含环境/租户/对象版本且每次返回前重新授权；Membership/关系/策略变化使旧范围失效 |
| 异步任务 | 载荷含可信范围快照、事件 ID、对象 ID 和版本；消费者重新解析租户状态并复核权限 |
| 文件 | COS key 按租户前缀隔离，校区对象继续分段；后端签发短时链接，不公开永久地址 |
| 日志 | 结构化记录租户/校区和请求关联 ID，但不记录敏感正文；平台运行日志与业务审计分离 |
| 审计 | 动作、对象、前后状态、操作者、范围、结果不可缺；普通业务角色不可修改 |
| AI 会话 | 会话、提示、检索上下文、教师摘要和删除请求绑定同一租户/校区/学生授权范围 |
| AI 成本 | 用量归属至少含环境、`tenant_id`、功能、会话和供应商请求标识；不得跨租户合并成可见明细 |

## 4. 校区与更细范围

- 机构级对象可使用空 `campus_id`，但必须明确其作用域为当前租户全机构，不能用空值绕过校区限制。
- 校区负责人只能访问 Membership 明确授权的一个或多个 `campus_id`。
- 教师进一步受班级、任务与学生范围约束；家长进一步受已通过且未解除的 `GuardianRelationship` 约束。
- 机构管理员的租户范围不自动等于所有敏感内容权限；学生、健康、接送、AI 等对象仍要求业务权限。

## 5. 数据库与事务守卫

未来数据访问层应使用范围化仓储或查询构造器，禁止无范围的通用 `findById` 进入业务代码。事务内新建、更新、关联和审计使用同一可信范围；发现跨租户外键、范围缺失或关联不一致时整体失败。

数据库级复合唯一约束、外键或行级安全可作为纵深防御候选，但不能替代应用层授权。本批次不选择或创建迁移。

## 6. 公共内容与缓存

公共接口只返回明确机构下 `PUBLISHED` 且 `PUBLIC` 的投影。缓存必须以租户和发布版本区分；下架事件使对应投影失效。缓存未命中可回源数据库，权限服务或数据库不可用时不得回退到其他租户或旧草稿。

## 7. 文件与短时链接

对象键示意：`tenants/{tenant_id}/campuses/{campus_id-or-tenant}/assets/{opaque_id}`。真实键由服务端生成，客户端不能自定前缀。上传和下载授权均短时有效、限定动作/对象/大小/类型；页面不保存或日志记录签名 URL。

## 8. 平台支持与跨租户例外

平台管理员默认只能见租户目录、状态和运行元数据。确需支持访问时必须同时满足：单独批准、明确工单/目的、指定租户与对象、最小字段、限时凭证、只读优先、全程审计、到期自动失效。未满足任一条件即拒绝。例外不得变成常驻角色权限。

## 9. 失败语义与未来验证

- 不存在与无权限使用相同通用响应，避免对象枚举。
- 客户端范围冲突返回权限错误，不做静默纠正。
- 异步任务缺范围、范围失效或对象跨租户时进入受控失败，不执行副作用。
- 未来测试至少覆盖同 ID 不同租户、跨校区、角色切换、缓存污染、任务重放、文件路径、AI 会话/成本和平台支持例外。

当前只定义这些门禁，不运行数据库、缓存、对象存储或真实权限测试。
