# 项目章程

## 1. 项目目的

为学生托管机构建立可演进的多租户 SaaS 技术与产品蓝图，先围绕“同芯学园”形成 Phase 1A 批次A的可审查交付，再由项目负责人决定是否进入后续阶段。

本批次验证的是范围、流程、信息架构、低保真交互、技术边界和安全门禁，不验证生产系统、商业上线或真实用户成效。

## 2. 授权与治理链

```text
项目负责人
→ AI产品与交付经理 + AI技术负责人
→ 专项智能体
→ QA/安全门禁
→ 项目负责人最终验收
```

- 项目负责人：批准基线、范围变更和阶段验收；
- 产品经理：定义做什么、为什么、用户流程与完成标准；
- 技术负责人：定义实现边界、数据/接口、安全、验证、发布与回滚草案；
- UI/UX智能体：按页面清单制作低保真结构与交互证据；
- QA/安全智能体：独立核验合同、隐私、安全、范围和证据；
- 专项智能体：只执行已批准任务合同内的白名单工作。

## 3. 当前授权

- 阶段：Phase 1A 批次A；
- 当前节点：A1 Git 与项目治理基线；
- 分支：`planning/phase-1a-batch-a`；
- 交付性质：规划、规格、草案、低保真原型与审查证据；
- 最终验收者：项目负责人。

本章程不授权 A2—A7 自动执行，也不授权批次B、Phase 1B、正式开发、发布或部署。

## 4. 成功条件

1. 合同12项交付均可追踪到文件、验收点和证据；
2. 术语、三端职责、多租户隔离、未成年人保护和 AI 边界无实质冲突；
3. V0.1 锁定信息不删弱漏，B级12项与三条关键闭环可操作；
4. 验证、提交、校验和与审查包均可复现；
5. 没有真实数据、正式模型、支付、生产密钥、推送或部署；
6. 最终 `PASS` 明确为内部证据门禁通过、待项目负责人验收；
7. 完成回执后停止。

## 5. 约束

- 技术底座按多租户设计，当前只围绕单机构试点；
- 只使用虚构模拟数据；
- 不连接腾讯云服务器、微信服务、伙伴云、支付、生产数据库或正式 AI；
- A0—A7 一律不安装依赖；浏览器能力不可用或失败时使用静态链接与内容检查，不以安装工具补救；
- 未来最小验证依赖只有在项目负责人批准新任务合同中的包名、版本、必要性、影响和回退，并先形成新版权威执行合同、新 SHA、原子更新全部引用且重新批准后才可安装；
- 不配置 Git 远程，不推送；
- 所有变更遵守 `CHANGE_CONTROL.md` 和任务合同。

## 6. 风险与处置

范围膨胀、来源冲突、合同哈希变化、真实数据或密钥暴露、跨租户设计缺失、AI越界、验证失败均为停止事件。执行者应保留已验证成果，记录事实、影响和最小解除条件，等待项目负责人裁决。
