# 职责矩阵

## 1. 角色定义

- **项目负责人**：基线批准、范围裁决、阶段验收和后续授权的唯一最终责任人。
- **AI产品与交付经理**：需求、范围、用户流程、信息架构、验收标准和交付协调。
- **AI技术负责人**：架构、数据、权限、多租户、API、验证、发布与回滚草案。
- **UI/UX智能体**：三端页面结构、交互、可访问性和低保真原型证据。
- **QA/安全智能体**：独立检查合同、功能、隐私、未成年人、租户、AI、安全和证据。
- **专项智能体**：在任务合同白名单内完成单一交付，不拥有范围决策权。

## 2. RACI矩阵

说明：R=执行，A=最终负责，C=会签，I=知会。

| 工作 | 项目负责人 | 产品经理 | 技术负责人 | UI/UX | QA/安全 | 专项智能体 |
|---|---|---|---|---|---|---|
| 冻结合同、阶段与八项裁决 | A | C | C | I | C | I |
| 任务合同与交付拆分 | A | R | R | C | C | I |
| 产品范围、角色、页面与流程 | A | R | C | C | C | R |
| 三端职责与信息架构 | A | R | C | R | C | R |
| 多租户、身份、权限与数据草案 | A | C | R | I | C | R |
| AI产品定位与提示流程 | A | R | C | C | C | R |
| AI安全与未成年人保护 | A | C | R | I | R | R |
| 低保真原型 | I | C | C | A/R | C | R |
| 自动验证与证据 | I | C | R | C | A/R | R |
| Git暂存与计划内提交 | I | C | A/R | I | C | R |
| 范围或基线变更 | A | R | R | C | C | I |
| 阶段 `PASS` 建议 | A | C | C | C | R | I |
| 下一阶段授权 | A | I | I | I | I | I |

## 3. 三端责任归属

| 端 | 产品责任 | 技术责任 | 设计责任 | QA重点 |
|---|---|---|---|---|
| 微信小程序 | 即时、现场、轻量流程 | 与统一 API/身份/权限一致 | 小屏、快捷操作、清晰状态 | 权限、上传、模拟数据、流程终态 |
| 用户网页端 | 完整查看、历史与长内容 | 与小程序共享业务规则 | 响应式、长内容、复杂编辑 | 双端一致性但不机械复制 |
| 机构管理网页端 | 配置、审核、表格、统计与批量管理 | 细粒度权限、审计、租户/校区范围 | 专业清晰、减少儿童化装饰 | 越权、跨租户、批量操作与审计 |

## 4. 决策边界

- 专项智能体无权新增功能、文件、依赖、远程或阶段；
- UI/UX智能体无权改变产品范围或安全规则；
- 产品经理无权豁免多租户、隐私和安全门禁；
- 技术负责人无权把草案升级为生产部署；
- QA/安全智能体可拒绝门禁，但不能代替项目负责人验收；
- 只有项目负责人可批准基线变更、接受风险或授权下一阶段。

## 5. 交接证据

每个责任人交接时必须提供：任务合同编号、变更文件、验收点、实际验证命令与结果、未解决风险、Git 状态/提交 SHA 和停止声明。没有证据的“完成”不进入下一责任环节。
