# 学生托管机构智能化系统平台 PRD

## 1. 文档边界

- 阶段：Phase 1A 批次A。
- 性质：产品规格基线，不是正式业务系统、测试环境或生产承诺。
- 试点语境：以“同芯学园”作为单机构试点设计语境，技术底座按多租户 SaaS 规划。
- 数据规则：本文示例均为模拟数据；不得使用可回溯到真人的学生、家长、教师或工作人员信息。
- 权威引用：范围与禁止事项以 `PHASE_1A_BATCH_A_CODEX_EXECUTION.md`、`docs/project/DECISION_BASELINE.md` 和 `docs/project/SCOPE_AND_NON_SCOPE.md` 为准。

## 2. 背景与问题

学生托管机构常同时承担公开展示、员工知识获取、家校协作、现场照护、内容运营与机构治理。信息散落在聊天、表格、文件和外部工具时，容易出现入口分散、重复录入、权限边界模糊、过程难追踪以及敏感数据暴露等问题。

本平台要先解决三个层次的问题：

1. 让访客能清楚了解机构、教师、活动、餐食、流程、校区与预约方式；
2. 让员工能从统一入口获取新人指南、教学资源和伙伴云快捷链接；
3. 为后续家长、教师、校区和平台治理能力建立一致的账号、权限、状态和审计边界。

当前阶段只把需求转化为可审查的规格与低保真原型，不验证真实业务成效。

## 3. 产品定位

产品定位为：

```text
多租户 SaaS 技术底座
+ 单个真实学生托管机构试点语境
+ 先验证合作意愿与流程可用性
+ 再逐步开发完整业务
```

它不是面向学生的开放社交产品，也不是用 AI 替代教师、家长或机构管理责任的自动决策系统。

## 4. 目标客户与用户角色

### 4.1 目标客户

- 首要客户：有一个或多个校区、需要统一公开内容和内部工作入口的学生托管机构；
- 试点客户语境：一家机构、一个校区；
- 平台经营侧：未来负责租户开通与平台运维的 SaaS 运营方，但默认不可查看学生具体内容。

### 4.2 用户角色

七类角色为：访客、家长、教师、工作人员、机构管理员、校区负责人、平台管理员。角色能力、使用端和数据范围见 `ROLE_MATRIX.md`。

学生首期没有独立账号；涉及学生的操作由已授权教师或家长从学生档案发起。

## 5. 价值优先级

| 优先级 | 价值 | 用户结果 | 当前证据 |
|---|---|---|---|
| P0 | 可信公开展示 | 访客能完成了解机构与联系/预约意向路径 | V0.1 页面、内容字段、访客流程 |
| P0 | 内部知识可达 | 员工能进入指南、资源、搜索与伙伴云入口 | V0.1 页面、员工流程 |
| P0 | 权限与数据边界 | 不同角色只见其租户、校区、班级或关系范围数据 | 角色矩阵、状态和后续架构草案 |
| P1 | 可追踪内容运营 | 管理员能创建、发布、下架、排序并留审计线索 | 轻量后台规格与发布流程 |
| P1 | 家校与现场闭环 | 绑定、请假、接送、日报等关键流程可追踪 | B级关键流程原型规格 |
| P1 | 受监督的学习引导 | 学生先尝试，系统分层提示，摘要只回流教师 | AI流程与安全边界 |

优先级只说明产品规划顺序，不代表已经开发或上线。

## 6. 三端产品形态

| 端 | 核心职责 | 典型能力 | 明确不承担 |
|---|---|---|---|
| 微信小程序 | 即时、现场、轻量、拍照上传与快捷处理 | 访客浏览、员工快速取用、家长/教师关键操作 | 长内容复杂编辑、批量后台配置 |
| 用户网页端 | 完整查看、历史、长内容与复杂编辑 | 公开内容、指南资源、家长历史、教师完整记录 | 机构级权限和批量内容治理 |
| 机构管理网页端 | 配置、权限、表格、统计、审核、财务与批量管理 | 内容、账号、审核、文件、日志 | 访客访问、未经授权的跨租户查看 |

三端共用统一后端、数据库、账号、权限、文件和业务规则，但页面按使用场景设计，不机械复制。

## 9. 非功能需求

| 类别 | 要求 | 当前验证方式 |
|---|---|---|
| 可用性 | 关键入口名称一致；空状态、错误状态和下一步明确 | 页面清单、流程和原型审查 |
| 可访问性 | 信息不只依赖颜色；主要操作有文本标签；键盘路径可理解 | 原型静态与浏览器检查 |
| 响应式 | 用户网页支持常见桌面与移动阅读；管理端优先桌面信息密度 | 低保真布局检查 |
| 安全 | 默认拒绝越权；敏感操作需权限、确认和审计 | 角色矩阵、验收条件 |
| 隐私 | 最小采集、目的限制、可关闭、可删除、可审计 | 内容字段与后续安全草案 |
| 多租户 | 机构对象有 `tenant_id`；校区业务有 `campus_id`；服务端可信注入范围 | 产品验收与后续架构草案 |
| 可追踪 | 页面、流程、状态、内容对象和验收点使用稳定 ID | 九份产品文档交叉引用 |
| 降级 | 外部能力或 AI 不可用时给出安全提示和人工路径 | 流程与状态模型检查 |

性能、容量、可用性百分比和恢复目标必须在真实负载与基础设施方案确认后定义；本阶段不虚构数值。

## 10. 隐私、安全与权限原则

1. 所有机构业务对象必须带 `tenant_id`，校区业务必须带 `campus_id`；服务端从可信身份和 Membership 自动注入范围，不信任前端租户 ID。
2. 查询、写入、唯一约束、缓存键、任务、审计、文件前缀、AI 会话和成本均按租户隔离。
3. 平台管理员默认不查看学生具体内容；跨租户访问需要单独批准、最小权限和审计证据。
4. 未成年人能力需监护人同意、教师或家长监督、最小采集、输入脱敏、输出安全、人工复核、可关闭、可删除和可审计。
5. 当前只使用明显虚构且标注为“模拟数据”的占位内容，不保存真实手机号、证件、地址、照片、健康、考勤、接送、成绩或家庭关系数据。
6. 不接入真实登录、短信、微信授权、微信支付、伙伴云 API、正式 AI、生产数据库或生产密钥。

## 11. 同芯AI学习助手定位

助手仅服务于“小学作业引导 + 错题巩固”。学生先尝试，再按第0、1、2、3层递进提示，最后进入巩固层生成1—3道同类题；不确定或高风险时停止并转教师。学习摘要只能回流教师。

明确禁止开放式万能聊天、代写、作弊、情感陪伴、虚拟好友、心理诊断、情绪识别、自动能力标签、自动纪律/处罚/绩效结论，以及未经教师或家长确认发送敏感结论。本批次不调用正式模型。

## 12. 成功指标框架

当前只定义测量口径，不给出未经试点验证的目标值：

| 指标 | 定义 | 数据边界 |
|---|---|---|
| 访客任务完成率 | 从访客首页到机构信息、教师、活动、餐食或联系/预约意向终点的完成比例 | 仅经同意的匿名事件 |
| 员工资源可达率 | 员工从工作台到指南/资源目标内容的成功比例 | 租户内最小事件 |
| 内容发布成功率 | 合法草稿经审核操作进入已发布且双端可见的比例 | 仅内容与审计元数据 |
| 绑定处理闭环率 | 提交的绑定申请进入已通过、已拒绝或已解除终态的比例 | 未来；按租户与关系隔离 |
| 教师日报自动汇总覆盖率 | 日报草稿中可由任务和现场记录自动汇总的字段比例 | 未来；不作为教师绩效结论 |
| AI提示有效率 | 学生先尝试后，经提示重新作答或完成巩固的比例 | 未来；仅授权试点、摘要回流教师 |
| 安全事件率 | 越权、隐私、代写或有害输出事件占受测交互比例 | 未来离线评测与审计 |

任何真实采集、基线和目标值都需后续独立批准。

## 13. 主要风险与应对

| 风险 | 影响 | 当前应对 |
|---|---|---|
| 合并信息架构导致需求丢失 | 页面看似减少但内容或验收点消失 | 用独立映射和验收 ID 保留企业文化、家校共育、校区联系、预约、资源搜索和排序 |
| 三端机械复制 | 操作负担与信息密度不匹配 | 按现场、完整查看、批量治理分别设计 |
| 权限只做前端隐藏 | 可越权访问其他租户或校区 | 服务端可信注入与默认拒绝写入验收标准 |
| 未成年人数据过度采集 | 隐私与安全风险 | 最小字段、监督、脱敏、关闭、删除、审计 |
| 教师日报退化为重复表单 | 增加教师负担、数据失真 | 未来由任务、考勤、接送、学生记录和异常自动汇总，教师只补充总结 |
| AI直接给答案或形成标签 | 学习与未成年人风险 | 先尝试、分层提示、转教师、禁止画像和自动结论 |
| 试点样本偏差 | 单机构结论不能代表市场 | 明确试点限制，不把主观反馈当普遍成效 |

## 14. 依赖与非范围

当前规格不依赖任何已安装外部包、真实服务或生产凭据。正式微信小程序、Next.js、管理后台、NestJS API、数据库迁移、外部集成、支付、正式 AI、云部署、Git 推送以及后续阶段均不在当前范围。
