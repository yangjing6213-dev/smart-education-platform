> 状态：本地离线准备稿。本文不是合同、收费政策、法律意见、服务等级承诺或真实运营记录。不得直接展示给真实机构或用于真实开停户、收款、退款、人员决定或客户支持。

## 1. 目的与使用范围

本稿把项目方案 R10 的费用核对、套餐与配额、租户开停、员工证照/招聘、机构开通培训、续费和支持流程整理为可填写的操作清单。当前仅用来梳理实现与决策缺口；真实主体、价格、合同条件、服务时限、联系方式和客户资料均未提供，也不在此猜定。

阶段顺序以“本地合成演示 → 负责人/专业人员补齐真实规则 → 明确授权后单独验证真实环境”为准。页面或测试出现固定样例只证明本机流程，不代表实际收费、退款、人员审查、租户开通或服务响应。

## 4. 费用核对与退款

G5.2 的固定流水是合成只读展示。真实账务启用前，应由财务负责人定义账单来源、应收与实收口径、币种/税费、退款原因与审批、对账频率和差异处理；本稿不录入或推断任何数值。

拟议人工核对顺序：

1. 确认核对期间、机构范围、账单/交易来源与版本；不得用客户端提交的租户或学生编号扩大范围。
2. 分开核对收费项、付款、退款、冲正和当前余额；每笔差异保留原始来源引用，不覆盖历史流水。
3. 将差异标为“待核对 / 需补材料 / 已核实 / 已批准更正”，由授权财务角色复核；未批准前不修改账务状态、不触发退款。
4. 将核对结果和未决项交给负责人，不向家长或平台运营展示超出其权限的学生级明细。

**待负责人/财务填写：** 账单来源、金额与税费口径、退款受理条件/额度/审批层级、对账周期、差异容忍规则、凭证/发票要求、记录保留依据、异常升级对象。任何空项都表示真实财务流程尚不能启用。

## 5. 套餐、配额与租户状态

G5.4 的固定套餐和配额是本地演示数据，不是销售方案。真实业务启用前，逐项确认功能范围、计量口径、限额、超额处理、变更生效时间、通知责任和申诉/人工复核办法；不得从演示样例推导价格或自动停服规则。

套餐/配额变更清单：申请范围 → 业务负责人确认合同版本 → 配额与影响说明 → 操作人更新 → 第二人复核 → 租户侧人工确认 → 记录生效版本与回退方式。任一项未确认时，保持原服务状态并转负责人处理；系统提示不能代替合同或人工决定。

**待负责人填写：** 套餐名称与版本、价格/税费、计量单位、各项上限、超额策略、提醒阈值、生效/终止条件、过渡期、争议处理人及回退方案。

## 6. 员工证照、招聘与工作回顾

使用 G5.3A/B 的本地功能时只核对合成记录。未来真实流程必须先明确资料收集依据、访问角色、核验来源、有效期维护、错误更正、到期提醒责任与资料删除/归档规则；本地到期提示不证明证照真实或合规。

- 证照核验由指定人工查看原始授权材料并记录结论类别、核验人、核验日期和复核日期；系统不判断真伪或法律效力。
- 招聘记录只辅助人工跟进；候选人评价、录用、薪酬和任职决定不得由系统自动产生。
- 工作回顾和绩效资料必须说明用途、来源、可见范围、申诉/更正入口和复核责任人；分数或汇总不得直接自动影响个人权益。
- 真实员工/候选人的姓名、联系方式、证照文件和评价材料不进入本地合成样例。

**待负责人/专业人员填写：** 可收集的证照类别及法律依据、核验主体、保存期限/删除规则、员工告知和申诉路径、招聘阶段定义、绩效数据用途、人工复核人与最终决定人。

### 续费/支持单据

支持事项的建议步骤为：受理编号 → 分类和范围核验 → 分派责任人 → 记录最小必要情况 → 给出已批准的处理说明 → 复核是否解决 → 关闭或升级。不得在支持记录中粘贴真实学生材料、证件、密码或密钥；需要诊断时先脱敏并走经批准的安全渠道。平台管理员不得因此取得学生正文访问权。

续费提醒、客户通知、支持服务时段、优先级和处理承诺都必须由负责人另行批准。本地支持队列仅展示固定合成状态，不代表真实工单已被受理或解决。

**待负责人填写：** 续费提前期、通知渠道/文案批准人、服务支持渠道、服务时段、严重程度定义、首响/解决目标（如需）、升级联系人、节假日安排、客户反馈/验收方式和服务终止交接。
